# 数据定义

刷卡事件以event_id去重，card保留前导零。route支持1路/01等别名。event_time必须带偏移；业务日为Asia/Shanghai。result仅success可作为行程，失败刷卡隔离。reported为实扣人民币元。票价F1至2026-11-01前为2元，F2为2.50元。

跨线路换乘必须在上一次实际付费行程后60分钟内，恰好60分钟排除。同线路无优惠；零付费行程不能延长换乘锚点。先扣1元换乘优惠，再对卡号业务日施加6元封顶。每条基本票价=实算扣费+换乘优惠+封顶优惠。

业务ID和超大整数按文本保形；Decimal参与数量金额计算，对外序列化为字符串。哨兵集合定义在app/values.py，缺失值不能当零。所有时间带UTC偏移，先转UTC比较，业务日按指定地区划分。区间统一[start,end)。重复业务键保留第一条、完全相同行计重复；值冲突行隔离且保留原值。空文件、全空白、仅表头分开拒绝。

运行清单包括输入sha256、规则版本、参数、生成时刻与耗时。源行编号以CSV解析器的逻辑记录物理起止行表示，引号内换行不增加记录数。输入超过4MB返回413，非法表头和类型返回422，失效版本复核返回409。

## 分块上传（月末超限批次）

单次请求上限4MB。超过上限的文件按字节切成 `parts` 块，依次 `POST /api/sources/<source>/parts/<n>`（multipart：`file`、`parts`、可选 `params`），收齐后 `POST /api/sources/<source>/finalize` 结算。分块只是传输边界，不是计算边界：

- 计算前把同一来源的全部分块按序拼成一个逻辑 CSV，再按「卡号 + 业务日」重新归集后统一走 1→7 阶段；换乘锚点、换乘窗和六元封顶只在归集后的完整卡日内裁决，不跨块接续状态。
- 分块可以切在记录中间甚至引号内换行中间；采信阶段按逻辑记录重新编号，并记录每条记录跨了哪些分块（`分块 1→2`）。
- 同一来源 `source` 是幂等键：重复上传同块（同 sha256）只刷新收块时间，不新增批次；同块不同内容、同来源参数或分块总数不一致均返回409，原始分块保留不覆盖。
- 未收齐时 finalize 返回409 `CHUNK_INCOMPLETE`；计算中断不落库，上一完整版本与复核状态保持不变。
- 已收分块与来源摘要保存在 SQLite `parts`/`sources` 表，结算后仍可用于复核与重算，不随批次清理。
- 来源总量上限64MB、最多256块，防止无限拼接占满内存。

## 来源行逐条去向

采信阶段给每条 CSV 逻辑记录分配 `_record`（1..input），去向为 accepted / quarantine / duplicate / blank / repeated_header 五类之一。清分阶段校验：每条记录恰好一个去向、编号连续无缺、采纳集合等于最终结果集合、隔离集合等于累计隔离集合。任一不满足即 `LINEAGE_INCOMPLETE`，日结拒绝封存，证据导出返回409。证据 CSV 每条来源记录一行，带记录号、物理行区间、所属分块、处理位置、原因、凭证、换乘与封顶依据。
